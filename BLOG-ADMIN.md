# Управление блогом

Админка находится по адресу `/blog/admin/`. Заказчик видит список новостей и форму с заголовком, описанием, текстом, обложкой, категорией и датой. HTML редактировать не нужно.

Все 12 исходных статей перенесены с полным содержимым: абзацами, заголовками разделов, списками, выделенными фразами и фотографиями внутри текста. Сохранённые пользовательские правки при восстановлении пропущенных блоков сохранены.

## Запуск на компьютере

1. Установите Node.js версии 22.12 или новее.
2. Запустите `start-site.bat` из папки проекта. Установка npm-пакетов для запуска готового сайта не требуется.
3. При первом запуске терминал покажет одноразовую ссылку. Откройте её и задайте свой пароль, не короче 12 символов. Логин — `admin`.
4. Обычный адрес админки: `http://127.0.0.1:8484/blog/admin/`.

Одноразовая ссылка перестаёт действовать после создания пароля. Не передавайте её посторонним. Пароль хранится в виде хеша в `data/admin.json`, вне публичной папки сайта.

Если пароль потерян: остановите сервер, переместите `data/admin.json` в безопасное место вне проекта и снова запустите сервер. Появится новая одноразовая ссылка. Статьи останутся на месте.

## Работа заказчика

- «Добавить новость» открывает пустую форму.
- «Загрузить изображение» принимает JPG, PNG и WebP. Браузер сохраняет сжатую обложку до 1600 пикселей и отдельную маленькую версию до 640 пикселей для карточек.
- «Сохранить черновик» сохраняет новость только в админке.
- «Опубликовать» добавляет её в блог. Три новости с наиболее поздними датами показываются на главной.
- «Сохранить изменения» обновляет опубликованную новость.
- «Снять с публикации» убирает новость с сайта и сохраняет её в черновиках.
- «Удалить» удаляет новость после подтверждения. Предыдущая версия остаётся в технической резервной копии.
- Текст вводится в визуальном редакторе. Выделите фрагмент и выберите размер шрифта, жирный, курсив или подчёркивание. Выравнивание действует на текущие или выделенные абзацы; доступны заголовки и списки.
- «Фото в текст» вставляет одну или несколько фотографий в положение курсора, в том числе между абзацами. Каждое фото автоматически сжимается до 1600 пикселей. В статье может быть до 50 фото. Выберите фото в редакторе, чтобы изменить его ширину, выравнивание или описание либо удалить его. Обложка для карточки задаётся отдельно.
- Для переноса зажмите фото левой кнопкой мыши и переместите к нужному абзацу: линия показывает место вставки. Пока кнопка зажата, колесо прокручивает страницу; возле верхнего и нижнего края окна работает автопрокрутка. Фото перемещается в одном экземпляре. Esc отменяет перенос, Ctrl+Z возвращает фото на прежнее место.
- «Отступы статьи» регулируют левую и правую границы содержимого от 0 до 20% ширины. Проценты сохраняются при просмотре с телефона.
- «Отступы фрагмента» над текстом задают дополнительные левый и правый отступы для текущего абзаца целиком. Можно выделить несколько абзацев и применить настройку только к ним. «Сбросить» убирает отступы выбранных абзацев, не меняя остальные. Отступы сохраняются при переключении абзаца в заголовок.
- Название новости становится H1. В списке «Тип текста» выберите «Заголовок H2» для раздела или «Подзаголовок H3» для подпункта. Размер шрифта и жирное выделение отдельно не превращают текст в заголовок.
- В разделе «SEO статьи» можно задать отдельные заголовок и описание для поиска и соцсетей. Пустые поля берут название и короткое описание новости. Они не меняют текст карточки и H1.
- «Предпросмотр» показывает текущие изменения в оформлении сайта до сохранения. В окне можно переключиться между компьютером и телефоном. Предпросмотр не публикует черновик.
- Ctrl+Z отменяет последнее действие в тексте. Enter начинает новый абзац, Shift+Enter переносит строку внутри абзаца.

После сохранения следующая загрузка блога получает обновлённые данные. Пересборка сайта для редактирования новостей не требуется.

## Где лежат данные

```text
data/
  admin.json                    хеш пароля; не публиковать
  blog/
    posts/<id>.json             оригиналы всех статей, включая черновики
    backups/                    предыдущие версии при изменении и удалении
public/blog/
  admin/                        HTML и стили интерфейса админки
  posts/index.json              лёгкий список опубликованных карточек
  posts/<slug>.json             отдельные опубликованные статьи
  article/<slug>/index.html     готовый HTML каждой опубликованной статьи
  uploads/                      загруженные обложки и фотографии статей
docs/blog/                      те же публичные данные в готовой сборке
dist/blog/                      копия готовой сборки
server/admin.mjs                небольшой сервер на встроенных модулях Node.js
src/admin/                      исходники редактора, собираемые только для админки
src/blog/content.js             общая проверка структуры текста; нужна серверу
src/blog/seo.js                 общие правила SEO-полей; нужна серверу
server/article-html.mjs         формирование статических страниц и карты сайта
```

Оригиналы с черновиками лежат за пределами публичного каталога. В публичный `blog/posts/` попадают только опубликованные статьи. Оформленный текст хранится в поле `content` как проверенная структура блоков, фотографий и выделений; `body` содержит обычный текст для совместимости. Старые статьи без `content` продолжают открываться. Список карточек не содержит полный текст и фотографии статьи. Tiptap загружается только в админке; на публичной странице работает небольшой React-компонент.

## VPS: минимальная нагрузка

Рекомендуемая схема: Nginx отдаёт `docs/` напрямую, а в Node.js направляет только `/blog/admin/api/`. Поэтому просмотры сайта и статей не требуют выполнения кода админки.

Каждая опубликованная статья получает адрес `/blog/article/<slug>/` и полный HTML с H1, H2/H3, описанием, оформленным текстом, фотографиями, Open Graph и разметкой BlogPosting. HTML обновляется при сохранении новости. При снятии с публикации или удалении публичный файл удаляется. Пересборка для изменения статьи не нужна.

Переменная `PUBLIC_ORIGIN` с реальным доменом задаёт основной адрес статьи (canonical), абсолютные ссылки для соцсетей и `sitemap.xml`. Карта содержит только опубликованные статьи и основные страницы; ссылка на неё добавляется в `robots.txt`. Если запускаете сборку отдельно на VPS, используйте тот же `PUBLIC_ORIGIN`. Локально без домена карту сайта не создаём. Админка и предпросмотр закрыты от индексации.

Запуск сервера из папки проекта:

```sh
PUBLIC_ORIGIN=https://example.ru ADMIN_SECURE_COOKIE=true TRUST_PROXY=true HOST=127.0.0.1 PORT=8484 node server/admin.mjs
```

Замените `example.ru` своим доменом. HTTPS и эти настройки нужны для рабочего сайта. Процесс запускайте от отдельного непривилегированного пользователя под systemd или другим менеджером процессов. Публичный каталог — только `docs/`, а не корень репозитория. Пользователь Node.js должен иметь право записи в `data/`, `public/blog/`, `docs/blog/` и `dist/blog/`; Nginx — право чтения в `docs/`.

Пример блоков для существующего HTTPS-сервера Nginx:

```nginx
root /var/www/tfm/docs;
index index.html;
error_page 404 /404.html;

location = /404.html {
    internal;
}

location / {
    try_files $uri $uri/ =404;
}

# Поддержка старых ссылок на статьи с ?slug=...
location = /blog/article/ {
    if ($arg_slug ~ "^[a-z0-9][a-z0-9-]{0,179}$") {
        return 301 /blog/article/$arg_slug/;
    }
    try_files $uri $uri/ =404;
}

location ^~ /blog/admin/api/ {
    proxy_pass http://127.0.0.1:8484;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    client_max_body_size 5m;
    add_header Cache-Control "no-store" always;
}

location ^~ /blog/admin/ {
    try_files $uri $uri/ =404;
    add_header Cache-Control "no-store" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Content-Security-Policy "default-src 'self'; img-src 'self' https: blob: data:; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; connect-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'self'" always;
}

location ^~ /blog/posts/ {
    try_files $uri =404;
    add_header Cache-Control "no-cache" always;
}

location ^~ /blog/uploads/ {
    try_files $uri =404;
    expires 30d;
    add_header X-Content-Type-Options "nosniff" always;
}

location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

При первом запуске на VPS сервер покажет ссылку настройки уже с вашим доменом. Переходите по ней после подключения HTTPS и проксирования API. Папки `data/blog/` и `public/blog/uploads/` включите в регулярную резервную копию VPS. При обновлении кода сохраняйте эти папки и `data/admin.json`; старую копию данных поверх живых статей не загружайте.

## Разработка и сборка

```sh
npm install
npm run check
npm test
npm run build
npm start
```

Сборка обновляет `docs/` и `dist/`, сохраняет все восемь маршрутов сайта и использует текущие оригиналы статей из `data/blog/posts/`. Сборку запускайте отдельно от активного редактирования, затем перезапустите сервер. При `npm run dev` Vite показывает публичный сайт; для входа и сохранения используйте сервер на порту 8484.

Полная версия интерфейса восстановлена из предоставленной сборки в `src/site/ExistingSite.jsx`. Её React runtime заменён обычными импортами. Блог вынесен в редактируемые компоненты `src/blog/Blog.tsx`. Исходная конфигурация зависела от отсутствующей `.figma/make/site.json`; теперь проект собирается локально без Figma.

Публичные страницы теперь открыты для индексации: убраны общий `noindex` и `Disallow: /`. Основной заголовок статьи — H1, внутренние заголовки — H2/H3. Рекомендации по названиям и структуре: [Google Search Central](https://developers.google.com/search/docs/appearance/title-link). При публикации формируется [разметка BlogPosting](https://developers.google.com/search/docs/appearance/structured-data/article). Формы заявки и квиз по-прежнему демонстрационные: их доставка менеджеру не входила в задачу админки блога.
