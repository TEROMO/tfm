# VPS tyumen-factory.ru

Сайт: https://tyumen-factory.ru/ — Nginx отдаёт статику. Админка: https://tyumen-factory.ru/blog/admin/ — логин `admin`, перенесён текущий локальный хеш пароля. Только `/blog/admin/api/` проксируется в Node.js. Опубликованы все 12 статей из Git; локальный черновик первой статьи не переносился.

## Доступ владельца

В PowerShell на этом компьютере:

```powershell
ssh -o IdentitiesOnly=yes -i "$env:USERPROFILE\.ssh\tfm_owner_ed25519" root@80.87.197.181
```

Вход SSH по паролю отключён. `root` пока доступен по ключам; отдельного пользователя с `sudo` владелец создаст позже. Служебный `tfm-site` не имеет `sudo`, пароля или интерактивного входа. Приватные ключи в `.ssh` доступны только владельцу Windows и SYSTEM. Не копируйте ключи в репозиторий. Сохраните их отдельно; при потере доступа остаётся консоль VPS в кабинете провайдера.

## Размещение

- `/srv/tfm/app` — исходники сервера, принадлежат root и недоступны приложению для записи.
- `/var/lib/tfm/public` — публичная сборка; только этот каталог читает Nginx.
- `/var/lib/tfm/private/blog` — оригиналы статей и история изменений.
- `/var/lib/tfm/private/admin.json` — хеш пароля; Nginx не имеет доступа к файлу.
- `/etc/tfm/site.env` — окружение службы, читается systemd от root.
- `tfm-blog.service` — Node.js на `127.0.0.1:8484` от `tfm-site`, автоперезапуск, ограничение памяти/CPU, запрет повышения прав, readonly-код и readonly-ресурсы редактора.
- Исходящий доступ Node.js ограничен localhost. При добавлении доставки писем потребуется отдельно разрешить соединение с выбранным SMTP-сервисом.

## Защита

UFW разрешает только TCP 80/443 и ограничивает новые подключения к SSH 22. SSH требует ключ, отключены пароли, X11, агент и туннели. Fail2ban защищает SSH, блокирует повторные неправильные пароли админки и целевые пробы секретных файлов. Проверены реальные правила блокировки IPv4 и IPv6.

Nginx ограничивает частоту запросов, число параллельных запросов, размеры и время загрузки. Вход и API имеют отдельные лимиты. Реальный IP посетителя задаёт Nginx; переданный клиентом `X-Real-IP` не используется. Приватные пути, служебные файлы и установка пароля через публичный API закрыты. Активны HTTPS, HSTS, CSP, nosniff и ограничения встроенных браузерных возможностей. Админка закрыта от индексации.

Обновления безопасности Ubuntu, продление сертификата и автозапуск служб включены. Журналы ограничены по размеру; ротация запускается ежечасно. Node.js установлен отдельно от apt: его обновления и обновления зависимостей проекта нужно проверять при обслуживании. При обновлении кода не заменяйте живые статьи, хеш пароля и загруженные фото старой копией из Git.

## Резервные копии

На VPS ежедневно примерно в 02:30–02:40 по московскому времени запускается `tfm-backup.timer`. Копии шифруются age и хранятся в `/var/backups/tfm`; удаляются копии старше семи дней. В архив входят статьи, фото, код, хеш пароля, сертификаты и настройки. Проверено расшифрование и совпадение исходных статей и хеша пароля.

На компьютере владельца задача Windows `TFM encrypted backup download` в 06:00 скачивает последнюю копию по SSH и сверяет SHA-256. Она работает, когда владелец вошёл в Windows и компьютер имеет сеть; пропущенный запуск догоняется при доступности. Локально сохраняются последние 14 скачанных копий. При выключенном или отключённом от сети ПК новую удалённую копию получить нельзя.

Каталог на ПК: `%USERPROFILE%\.ssh\tfm-server-backups`. В нём находятся зашифрованные архивы, приватный `backup-age.key`, скрипт `pull-backup.ps1` и результат последнего скачивания `last-backup-status.json`. Каталог доступен только владельцу Windows и SYSTEM. Ключ восстановления следует также сохранить на отдельном защищённом носителе; без него архивы не расшифровать.

Восстановление сначала выполняйте в отдельный каталог с проверкой содержимого. На Linux с установленным age:

```sh
mkdir -m 700 restore-check
age -d -i backup-age.key tfm-YYYYMMDD-HHMMSS.tar.gz.age | tar -xzf - -C restore-check
```

Архив содержит приватные файлы. Не извлекайте его в публичный каталог сайта. После восстановления на другом VPS проверьте владельцев файлов, ключи доступа и настройки служб.

## Проверка работы

```sh
systemctl status tfm-blog nginx fail2ban
journalctl -u tfm-blog -n 50 --no-pager
fail2ban-client status
ufw status verbose
systemctl list-timers tfm-backup.timer certbot.timer
```

## Что остаётся вне этой настройки

Формы заявки и квиз пока демонстрационные: отправка заявок менеджеру ещё не подключена. Перед использованием сайта для приёма заявок нужен настоящий обработчик с ограничением отправок и проверкой спама.

Включение 2FA в кабинете хостинга, у регистратора и в GitHub выполняется владельцем аккаунтов. Для защиты от атаки, которая забивает сетевой канал VPS, нужен анти-DDoS на стороне провайдера или внешнего сервиса. Локальные лимиты и Fail2ban не гарантируют защиту от такого объёма трафика.
